# Подключение Start. к существующему проекту

Код клиента и SQL используют только схемы `start` и `start_private`.
Auth общий для проекта. Приложение удаляет только собственный профиль и данные,
сохраняя `auth.users` и данные соседних приложений.

## Однократная настройка

1. Проверьте существующие политики и Auth-триггеры общего проекта: новый
   пользователь Start. получает роль `authenticated`, но не должен автоматически
   получать права или профиль в соседних приложениях.
2. Добавьте [миграцию](migrations/202611130001_start_sync.sql) в общую историю
   миграций этого проекта и примените её. Для первичной проверки можно выполнить
   файл целиком через SQL Editor. Повторно запускать уже применённый файл не нужно.
   Не используйте `db reset` или несогласованный `db push` на общем проекте.
3. В настройках Data API добавьте **`start`** к существующим Exposed schemas.
   `start_private` остаётся закрытой. Существующие схемы сохраните.
4. В Auth Providers включите **Web3 / Solana**. Добавьте точные production URL
   и локальные адреса входа, например `http://localhost:1234/`, в Redirect URLs.
   Провайдеры и URL других приложений сохраните.
   [Supabase проверяет домен и URI подписи](https://supabase.com/docs/guides/auth/auth-web3),
   поэтому адрес входа должен совпадать с разрешённым URL, включая завершающий `/`.
5. Создайте `.env.local` по `.env.example`. Для клиента нужен только publishable
   key. Файл `.env.local` игнорируется Git. Secret/service-role key в Vite
   не добавляется.
6. Перезапустите dev-сервер. Откройте «Настройки → Синхронизация», создайте
   фразу, сохраните её и подключите второй браузер по той же фразе.

Для локального входа используйте `http://localhost:1234/`, для preview —
`http://localhost:4173/`. Supabase Auth v2.197 принимает HTTP только с
`localhost`; IP-адреса не проходят
[проверку домена SIWS](https://github.com/supabase/auth/blob/v2.197.0/internal/utilities/siws/helpers.go).
В production используйте HTTPS.

Браузер хранит данные `127.0.0.1` и `localhost` раздельно. Если прежние локальные
данные были созданы на IP-адресе, экспортируйте их в JSON на прежнем адресе
и импортируйте на `localhost`. Для открытия прежнего адреса при необходимости
запустите `npm start -- --host 127.0.0.1`. Миграция не удаляет его хранилище.

Realtime, Storage, Edge Functions и pgvector для текущего клиента не нужны.
Изменения отправляются очередью, получаются по таймеру, при фокусе и возвращении
сети; кнопка «Синхронизировать» запускает обмен сразу.

## Проверки

- `npm run check`
- `npm run test:smoke` — транзакции, миграция, очередь, конфликты и подпись ключа.
- `npm run test:sync` — точная SQL-миграция в PostgreSQL/PGlite с ролями и RLS.
- `npm run build && npm run test:e2e` — production-клиент в браузере, включая
  два устройства и потерю ответа после серверного commit. В этих сценариях
  Auth заменён тестовым шлюзом; SQL исполняется настоящим PostgreSQL/PGlite.
  Запросы тестов не попадают в пользовательский Supabase.

Проверки SDK/SQL через тестовый шлюз не заменяют проверку провайдера Auth
в выбранном облачном проекте после однократной настройки.

## Текущие границы

- Сид-фраза и закрытый ключ обрабатываются в браузере. Сессия хранится в
  IndexedDB; JSON экспорта их не содержит.
- `start.records` хранит типизированные логические сущности в общем конверте
  `{kind, id, data, revision, deleted}`. RPC валидирует содержимое и связь
  подписки с колонкой. Клиентские INSERT/UPDATE/DELETE отозваны.
- Подтверждённые изменения и receipts записываются в той же транзакции.
  Номера выдаются под блокировкой строки аккаунта.
- Поддерживается импорт прежнего JSON в локальный профиль, исходный legacy
  JSON сохраняется как резервная копия. Новые изменения пишутся в IndexedDB.
- Полный backup v2 содержит также архив наблюдений исходных ML-профилей.
  Импортированные наблюдения архивные; новый учёт ведётся отдельным профилем.
- При создании пустого облачного профиля локальные данные переносятся
  автоматически после явного включения синхронизации. Подключение существующего
  профиля загружает облако и сохраняет гостевые данные отдельно.
- Объединение двух заполненных профилей и staged replacement облачного
  профиля пока не реализованы; замена импортом доступна только локально.
- Физическое удаление старого архива ML ещё не настроено. На Free контролируйте
  размер базы, журналов и снимков; квота общая с соседними приложениями.
- Модель остаётся локальной. Завершать или переобозначать чужое 24-часовое
  наблюдение принимающий браузер не должен.
- Рабочее окно CTR ограничено активными наблюдениями и последними 10 000
  завершёнными наблюдениями за 90 дней исходного профиля. Полный архив
  сохраняется отдельно от этого окна и включается в backup v2.

## Состояние выбранного проекта

URL и publishable key добавлены в игнорируемый `.env.local`.
13 ноября 2026 года миграция `202611130001` применена через SQL Editor
в проекте `gouwunhbxbmkvltrxmrn`. Все девять таблиц Start защищены RLS;
прямых прав записи у `anon` и `authenticated` нет. Контрольная сумма тел
всех 18 функций совпала с локальной миграцией
(`587faba2a37cf535ff4a8573ea158a44`, MD5 используется только для сверки).

В Data API к прежним схемам добавлена `start`; `start_private` не опубликована.
Проверка настоящего API подтвердила отказ `42501` для анонимного обращения
к Start и `PGRST106` для служебной схемы. Провайдер Solana включён,
добавлены рабочие Redirect URLs `http://localhost:1234/` и `http://localhost:4173/`.
Перед использованием на production-домене добавьте его точный URL входа
в allow list этого общего проекта.

Реальная проверка 13 ноября 2026 года подтвердила вход по одной фразе
с обоих локальных URL, сходимость независимых изменений, идемпотентный повтор
после серверного commit, защиту ручного unread, общую историю кликов с
сохранением исходного прогноза и запрет прямой записи authenticated-клиентом.
После проверки удалены данные Start и временный пользователь Auth вместе
с identities и sessions. SQL подтвердил отсутствие записей тестового UUID;
Auth перестал принимать его сессию.

Read-only аудит 13 ноября 2026 года обнаружил только `public.sync_data`:
RLS выключена, у `anon` и `authenticated` есть права чтения и изменения;
пользовательских триггеров на `auth.users` нет. Права `sync_data` требуют
отдельного исправления с учётом использующего её приложения. Миграция Start.
не изменяет эту таблицу, её grants или существующие настройки Auth.
