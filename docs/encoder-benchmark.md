# Компактный encoder: техническая проверка

Дата: 12 ноября 2026 года. Связанный [план](click-probability-plan.md), этап 0.

**Результат: encoder-only граф работает в настольном Chromium. Проверка
на настоящем iPhone/Safari/PWA и оценка качества CTR ещё не выполнены.**
Проверка проводилась на локальном сервере, а не на production-хостинге.

## Обнаруженная ошибка исходного артефакта

Публичный `onnx-community/rubert-tiny-ONNX` на ревизии
`9a8d2ed31c37246d2a8d4d9f500dc1ca66563114` имеет конфигурацию
`BertForPreTraining`. Реальный запуск файла `model_quantized.onnx` в браузере
возвращает только `logits` размерности `[1, 18, 29564]` для пробной фразы.
Это предсказания словаря MLM, а не 312-мерные смысловые признаки.
Прямое использование первых 312 чисел было бы ошибкой.

Подготовлен [скрипт извлечения encoder](../scripts/ml-extract-encoder.py).
Он проверяет SHA-256 исходника, выбирает выход последнего encoder LayerNorm
`/bert/encoder/layer.2/output/LayerNorm/Add_1_output_0`, добавляет выход
`last_hidden_state` и удаляет недостижимую MLM-голову через ONNX Extractor.
Веса encoder не переобучаются. Полученный граф проходит `onnx.checker`.

| Артефакт                    |      Байты | SHA-256                                                            |
| --------------------------- | ---------: | ------------------------------------------------------------------ |
| Исходный q8                 | 12 089 905 | `b57b049fbe8a567203f86b8172b56df1c8c74d1900827ed665ee2efa649c0774` |
| Encoder-only q8             | 11 861 949 | `1d6a20cc6c15e206e91417b998bd333a06cab08116410c37e208670ca5159a7a` |
| Encoder-only fp32, контроль | 46 832 244 | `e2440591f1fe870aa0e6488eda1e858882f872ee53c834c003057e9d80522dcb` |

Выход исправленного графа: `last_hidden_state`, `[batch, tokens, 312]`.
Берётся CLS первого токена и нормализуется по L2 согласно рецепту автора.
На восьми коротких русских, английских и смешанных фразах cosine между q8
и fp32 CLS составил **0,998828–0,999356**. Эталон — тот же опубликованный
ONNX-граф в fp32 с извлечённым encoder, а не независимый PyTorch-запуск.
Это проверка согласованности квантования, а не доказательство качества CTR.

## Измерения

Среда: Apple M4, macOS arm64, Headless Chromium 158.0.8127.18,
Transformers.js 4.3.2, ONNX Runtime Web 1.31.0-dev.20260914-8d85527a0,
WASM, один поток, лимит 128 токенов. Runtime — зависимость выбранного
Transformers.js; dev-версию необходимо учитывать при закреплении production-комплекта.

| Измерение одного прогона                              |                                         Результат |
| ----------------------------------------------------- | ------------------------------------------------: |
| Передача полного q8-комплекта с gzip, включая runtime | 15 398 049 байт с учётом Resource Timing overhead |
| Суммарный распакованный размер запрошенных файлов     |                                   40 007 506 байт |
| Холодная готовность на localhost                      |                                        2 384,7 мс |
| Готовность новой страницы с тёплым кэшем              |                                          501,9 мс |
| Первое короткое предсказание                          |                                           40,4 мс |
| Короткий ввод, медиана / P95 из 20 запусков           |                                      4,2 / 5,0 мс |
| Ввод 128 токенов, медиана / P90 из 10 запусков        |                                    29,8 / 30,3 мс |
| Сетевые запросы ML-файлов при тёплом запуске          |                                                 0 |

Gzip применён локальным сервером ко всем файлам. Production должен подтвердить
такое же сжатие. Контрольный fp32-файл загружался отдельной фазой проверки и
не включён в размер q8-комплекта. Скорость localhost не является скоростью
скачивания по мобильной сети. Инициализация и инференс в измерительном harness
выполнялись на странице: отзывчивость продуктового worker этим не проверена.
Потребление памяти и энергии пока не измерено.

## Важная настройка кэша

При `env.backends.onnx.wasm.wasmPaths = '/ort/'` в этой версии обёртки
WASM повторно передавался при открытии новой страницы: около 6,68 МБ gzip.
Кэш runtime включается с явным объектом URL, содержащим оба поля:

```js
env.allowRemoteModels = false
env.allowLocalModels = true
env.localModelPath = '/models/'
env.useWasmCache = true
env.backends.onnx.wasm.numThreads = 1
env.backends.onnx.wasm.wasmPaths = {
    mjs: new URL('/ort/ort-wasm-simd-threaded.asyncify.mjs', location.href)
        .href,
    wasm: new URL('/ort/ort-wasm-simd-threaded.asyncify.wasm', location.href)
        .href,
}
```

С этими настройками повторный запуск использовал Cache Storage и HTTP-кэш
без запросов файлов к измерительному серверу. Кэширование оболочки приложения
и автономный старт PWA этим не реализованы.

## Воспроизведение

[Браузерный probe](../scripts/benchmark-encoder.mjs) не скачивает зависимости
или модели автоматически. Он требует локальные каталоги и установленный
Chromium Playwright. Зависимости ML для эксперимента устанавливались отдельно
в `/tmp`, без изменения package.json приложения.

1. Подготовить локальный npm-каталог с `@huggingface/transformers@4.3.2`.
2. Скачать с закреплённой ревизии исходные `config.json`, `tokenizer.json`,
   `tokenizer_config.json`, `onnx/model_quantized.onnx` и `onnx/model.onnx`.
3. В отдельном Python-окружении установить `onnx==1.23.2`. Запустить
   `ml-extract-encoder.py SOURCE DESTINATION` отдельно для q8 и fp32.
   Подкаталог модели должен сохранить имя `onnx-community/rubert-tiny-ONNX`.
4. Скопировать конфигурацию и токенизатор в каталог извлечённой модели.
5. Выполнить из корня проекта:

```sh
node scripts/benchmark-encoder.mjs \
    --runtime-dir /tmp/start-encoder-spike/node_modules \
    --model-dir /tmp/start-encoder-spike/encoder-models \
    --variant encoder-only \
    --output-dir output/encoder-benchmark/encoder-only
```

Результат сохраняется в игнорируемый `output/encoder-benchmark/encoder-only/result.json`:
характеристики окружения, версии runtime, SHA-256 весов, выходы графа,
прогоны, сравнения q8/fp32 и список реально переданных ресурсов.
Исходный публичный граф должен завершать probe ошибкой отсутствующего hidden state.

## Оставшиеся проверки перед продуктовым включением

- Настоящий iPhone: Safari и standalone PWA, память, возврат из фона и перезапуск.
- Production-раздача, gzip и политика кэша с реального хостинга.
- Worker, отмена загрузки, потеря кэша и отсутствие ML-запросов до включения.
- Корректность полного препроцессинга RSS и устойчивость к пустым/длинным текстам.
- Репрезентативная выборка русских лент и затем сравнение будущих CTR-прогнозов.
- Закреплённый комплект runtime, манифест контрольных сумм и атрибуция модели.

## Источники и атрибуция

Базовая модель — `cointegrated/rubert-tiny`, автор `cointegrated`, лицензия MIT
согласно карточке модели. Исходный ONNX экспорт опубликован `Felladrin`
в `onnx-community`; производный граф следует сопровождать ссылками и лицензией
базовой модели. Лицензии JS-runtime необходимо поставлять вместе с runtime.

- [Автор модели и рецепт CLS](https://huggingface.co/cointegrated/rubert-tiny).
- [Закреплённая ревизия ONNX](https://huggingface.co/onnx-community/rubert-tiny-ONNX/tree/9a8d2ed31c37246d2a8d4d9f500dc1ca66563114).
